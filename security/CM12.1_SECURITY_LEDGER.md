# CM12.1 security ledger

Authoritative ledger for all ASB research, applicability decisions, backports and
security validation for this project. Scope: actual `/home/airi/LG_K7/cm12`
Android5.1.1/API22 source and selected `kernel/lge/m1-custom` only. CM13 must
not be investigated, patched or security-tested without explicit owner request.
This scope restriction applies to helpers, patch searches and future handoffs.

## Decision rules

- **Applicable:** vulnerable code/conditions match this source and selected build.
- **Not applicable:** evidence proves the affected implementation or necessary
  configuration is absent; absence from a bulletin version list is insufficient.
- **Already patched:** source comparison proves all relevant fix changes or an
  equivalent fix are present; a commit title or SPL date alone is insufficient.
- **Unknown:** applicability/equivalence remains unproven.
- **Blocked:** confirmed applicable, but a named dependency or unavailable fix
  prevents remediation. Record the reason and next action.

Applicability status is separate from implementation and validation. A locally
applied patch stays Applicable with its fix commit and validation state recorded;
it becomes Already patched when audited against a later explicitly pinned
baseline. Never count compilation, patch application, or a missing CVE string as
proof of vulnerability closure. Keep selected build configuration and source
changes linked to each finding. Avoid parallel competing ledgers. Evidence
files and patch artifacts support this ledger; they are not separate ledgers.

## First small batch and validation gates

Start with CVE-2016-5195 alone; select additional fixes only after source review.
Record upstream provenance and dependencies, local fix commit and diff hash,
affected configuration, compilation result, targeted behavioral/security test,
and hardware regression result separately. Build success is not runtime proof.
Do not flash or run destructive privilege-escalation proofs as part of research.
Security candidates are not the hardware-qualified release until tested.
Then review post-baseline bulletins in order while also checking missing older
fixes; declared SPL cannot substitute for auditing the custom kernel.
